## 已复现并修复

| 优先级 | 问题与影响 | 修复 |
|---|---|---|
| 高 | 分块运行漏掉全局测量一致性检查。同一 assay 在两个染色体使用不同单位，或不同染色体使用不同 Hi-C 分辨率时，整批运行拒绝，分块运行却成功。`predict` 默认分块，因此影响实际工作流。 | 分块前流式收集去重后的接触测量定义，复用整批校验；合并前检查各分块已解析活性信号的单位、归一化和窗口。失败时不发布结果目录。 |
| 高 | `fit-hic` 按 bin 中心拟合距离和边界衰减，但 `prior_only`、固定权重收缩及观测模式中的先验计算未遵循已保存的坐标策略。边界落在 TSS 与其 bin 中心之间时，跨边界与否会改变。 | `contact_prior` 统一遵循拟合资产的坐标策略，输出记录实际策略。未声明策略的既有先验保持原始基因组锚点行为；逐对收缩保留 bin 中心行为。 |
| 中 | `binary_metrics` 在验证标签之前转换为整数，`0.2`、`-0.2` 被变成 0，`1.9` 被变成 1，可能掩盖错误标签。标准功能标签导入路径本来产生 0/1，因此主要影响直接调用该函数的分析。 | 先检查标签确为 0/1，再转换整数；非法输入给出明确错误。eQTL 软标签仍使用独立的 soft AP 函数。 |

坐标问题的可复现例子：500 bp 分辨率，元件锚点 5249、TSS 10000；bin 中心为 5250、10250。边界在 10100，强度 1，先验 a=1、gamma=1、beta=1、d_ref=d_min=500。旧计算为 0.105241，新计算为 0.036788，旧值约为正确值的 2.86 倍。这是接触先验的差异，不表示最终归一化评分也必然变化同样倍数。

## 主模型的判断

当前源码使用：

```math
S_{eg}=A_e\overline C_{eg}B_{eg}^{\eta},\qquad
B_{eg}=\frac{\overline C_{eg}}{\sum_{h\in\mathcal G_e}\overline C_{eh}},\qquad
\mathrm{PACE}_{eg}=\frac{S_{eg}}{\sum_{j\in\mathcal E_g}S_{jg}}.
```

这里两个归一化方向不同：B 在同一元件的候选基因之间归一化，最终 PACE 在同一基因的候选元件之间归一化。代码使用对数支持度，避免直接乘积溢出破坏排序。eta=0 时不要求 B 完整；eta>0 时，某个元件缺少候选基因接触值，会使该元件的分配无法完整求解。这与当前固定候选集设计一致。

- 默认缺失分母时不发布完整主评分；条件评分与敏感性上下界单独给出。这比直接丢弃缺失项后仍称为完整评分更严谨。
- 多 TSS 权重在基因层面共享，实测零与 NA 区分，技术重复、生物学重复和供体分层聚合，方向合理。
- 当前默认模型不是任意多组学信号直接相乘。额外组学主要作为注释或单独的 ML 输入；论文描述应与实际运行配置一致。
- B 是候选集内接触份额，不是经实验校准的增强子—靶基因因果概率。候选基因集合的改变会影响 B，需要做窗口与注释敏感性分析。
- CTCF 方向推断的边界是待验证候选边界；beta=0 仅消除边界衰减，不自动保证整个预处理流程与原版 ABC 相同。
- 代码将 eQTL PIP 校准与功能验证区分开，保留染色体最终测试集；这是必要设计。PIP 汇总的独立性假设、不同组织 eQTL 的可转移性仍是科学假设。

## 下一阶段应优先补的证据

1. **公平外部基准**：对齐候选元件、活性面板、TSS、接触输入和测试标签；比较 ABC、PACE、距离基线及接触幂次基线。冻结参数后报告 AP、AUROC、覆盖率和漏掉的阳性数量。
2. **家养动物低数据量验证**：对 Hi-C 原始计数进行不同深度的抽样，检验收缩是否改善稀疏数据表现；对 TSS 注释缺失、单层活性和跨组织先验分别测试。不能只展示完整数据上的合成示例。
3. **分项消融**：固定其它条件，分别评估边界项、收缩、多 TSS、B 项。gamma 和 eta 可能共同改变距离偏好，需确认增益不只是距离衰减变陡；仓库已有 `contact_power_2` 比较，可继续扩展匹配的距离基线。
4. **评估单位**：eQTL 目前按染色体汇总 soft AP，可补每基因排序指标与基因宏平均，避免基因候选数量和组成评分影响解释。报告染色体/位点层面的不确定性，不把相关元件当作独立重复。
5. **规模验证**：本次只验证小型真实格式文件和合成工作流。百万级候选边、大型 cooler 读取、内存与耗时，以及最低依赖版本和多平台运行仍需独立记录。

这些是后续验证工作，并未在本次修复中宣称已经完成。软件工程质量和生物学预测性能需要分别证明。
